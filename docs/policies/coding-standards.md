# 코딩 정책

목표: **누가 짜도 같은 모양의 코드**, **같은 로직은 한 곳에**. 새 코드를 쓰기 전에 비슷한 기존 코드를 먼저 찾아 그 형태를 복제(패턴)하되, **코드 자체를 복사하지는 않는다.**

## 1. 일관성 (패턴을 따른다)

- 새 기능은 기존의 같은 종류 기능과 **파일 배치·이름·흐름이 같아야** 한다. 더 좋아 보이는 방식이 있어도 이 변경에서 혼용하지 않는다. 개선하려면 기존 코드 전체를 함께 옮기거나, 별도 제안으로 분리한다.
- 요청 하나를 처리하는 컨트롤러 액션은 항상 `검증(ModelState) → 권한 → 프로시저 호출 → JsonOk/JsonFail` 순서 ([backend.md](../architecture/backend.md)).
- 요청 입력은 `Input*` DTO(`Models/*Dtos.cs`)에 `[Required] [StringLength] [Range]` 와 **한국어 ErrorMessage** 로 선언한다. 액션 파라미터가 3개를 넘으면 DTO 로 묶는다.
- 프로시저 결과 DTO 와 요청 DTO 를 섞지 않는다 (`XxxItem` = 조회 결과, `Input*` = 요청).
- 매직 스트링(상태값 `'DRAFT'`, 역할 `'ADMIN'`, 세션 키, 카테고리 코드)은 상수/열거 한 곳에 정의하고 참조한다 (`SessionKeys`, `UserRoles`, `TitleAligns`, `BodyFonts` 가 기존 예).

## 2. DRY

**같은 로직이 2곳에서 필요해지는 순간이 올리는 시점**이다. 3번째까지 기다리지 않는다.

| 중복이 생기는 곳 | 올릴 위치 |
|---|---|
| 컨트롤러 간 공통 (권한 거부 응답, 결과→JSON 변환, 접근 조회) | `BaseController<T>` |
| 컨트롤러 밖에서도 쓰는 도메인 로직 (HTML 정제, 사양 생성, 업로드) | `Utils/` 클래스 + DI 등록 |
| 서버·클라이언트가 같이 쓰는 기본값/상수 | 서버(C#)를 원본으로 두고 `/api/auth/me`의 `BOOTSTRAP`으로 내려준다 (`HeadingStyle.ClientDefaults`) |
| 화면 간 공통 TS (라벨 맵, 포맷 함수, 모달 헬퍼) | `web/src/features/` 또는 `web/src/design-system/` |
| 문서 모양 (미리보기/PDF/편집기) | `DocumentHtmlBuilder` + CSS 변수 |
| 여러 프로시저가 공유하는 규칙 | SQL 함수 `UFN_S_*` (권한 판정이 기존 예) |
| 크기·색 등 스타일 값 | CSS 변수 (`doc-type.css`) |

- 붙여넣기 전에 자문: "이 코드가 바뀌면 다른 복사본도 같이 바꿔야 하는가?" 그렇다면 공통화한다.
- 공통화하려고 **기존 호출부까지 옮길 때는** 동작이 바뀌지 않게 하고, 범위를 그 중복 제거로 한정한다 (무관한 리팩터링 금지).
- 반대로 **우연히 비슷한** 코드(지금은 같지만 바뀌는 이유가 다른 것)는 합치지 않는다. 억지 추상화(매개변수 플래그 남발)보다 약간의 중복이 낫다.
- 권한 로직은 예외 없이 한 곳: **DB 함수**. C# 이나 JS 에서 재구현하지 않는다.

## 3. C# 스타일

- `Nullable` 활성. DTO 는 `= null!` (필수) / `?` (선택) 로 의도를 드러낸다. 새 경고를 만들지 않는다.
- 파일 범위 `namespace ExodusSystemManual.<폴더>;`. 컨트롤러 클래스 위에 `[Route]`, 액션은 `[HttpGet("kebab")]` 등 명시.
- 모든 쓰기 액션: `[AjaxAuth] [HttpPost/Delete] [ValidateAntiForgeryToken] [Produces("application/json")]`.
- 예외는 **경계(외부 시스템 호출: Playwright, datasheet DB, SMTP)에서만** 잡고 `_logger.LogError(ex, "...({MID})", mid)` 후 JsonFail. 업무 실패는 예외가 아니라 `ResultModel` 로.
- 로그는 구조적 템플릿(`{MID}`) 사용, 문자열 보간 금지. 비밀번호·토큰·HTML 본문은 로그에 남기지 않는다.
- 사용자에게 보이는 메시지는 **한국어**, 존댓말 어미 없이 간결하게 (기존 문구 톤 유지).

## 4. TypeScript / SQL 스타일

- TypeScript: [frontend.md](../architecture/frontend.md)의 API·Vue 패턴을 따른다. 전역 스크립트나 jQuery를 새로 만들지 않는다.
- SQL: `SET NOCOUNT ON`, `CREATE OR ALTER`, 대문자 키워드·컬럼, 소프트 삭제 조건, 감사 컬럼 갱신. 자세한 건 [database.md](../architecture/database.md).

## 5. 주석·문서

- 기본은 주석 없음. **왜(제약·함정·결정)** 가 코드에서 안 보일 때만 한국어로 한 줄. 무엇을 하는지 반복하는 주석은 쓰지 않는다.
- 삼중 슬래시 `///` 는 이 코드베이스가 클래스/DTO 속성의 **의미**(예: `SEC_TYPE` 값의 뜻)를 설명할 때 쓰는 관례다 — 같은 용도로만 쓴다.
- 동작을 바꾸면 관련 `docs/` 를 같은 변경에서 갱신한다.

## 6. 테스트

- 백엔드 로직을 추가·수정하면 같은 변경에서 테스트를 추가·수정한다. 규칙은 [testing.md](../workflows/testing.md).
- 테스트하기 어려운 구조(컨트롤러 안의 로직, 정적 전역 상태)를 만들지 않는다 — 순수 함수/주입 가능한 클래스로 분리한다.

## 7. 변경 범위

- 요청받은 것만 바꾼다. 인접 코드의 스타일 정리·이름 변경·포맷 재정렬을 섞지 않는다 (diff 가 커지면 리뷰와 되돌리기가 어려워진다).
- 파일 인코딩/줄바꿈/들여쓰기는 **수정하는 파일의 기존 것을 유지**한다 (`.csproj` 는 BOM 있음, JSON/JS 는 파일마다 들여쓰기 폭이 다름). 에디터 자동 포맷으로 전체 파일이 바뀌지 않게 한다.
- 의존 패키지 추가는 이유와 함께 사용자에게 먼저 확인한다.
